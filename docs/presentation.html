01 · THE ENGINEERING PROBLEM
Why Generic AI Analytics Fails in Production

Dashboards Show What Changed. Raw LLMs Hallucinate Why.

When a commerce business sees net margin drop across 500,000 order lines, owners need a provable root cause and a safe recovery plan — not unverified prose or blind API mutations.

FAILURE MODE 01 Contract R-10

Invented Financial Math

Prompting an LLM over raw CSVs produces fabricated revenue deltas, miscounted restockable COGS on returns, and non-reproducible numbers across runs.

Fix: LLMs never compute numbers. All KPIs live in deterministic Python/SQL modules.
FAILURE MODE 02 Contract R-11 / R-12

Zero Evidence Provenance

Black-box text summaries mix confirmed dataset facts with model hypotheses and user guesses, without citing dataset IDs, date windows, or row counts.

Fix: Every claim binds to an immutable EvidencePayload and passes a deterministic critic.
FAILURE MODE 03 Contract R-13

Uncontrolled Side Effects

Giving an LLM agent direct write tools risks unapproved customer contact, spreadsheet formula injection, or duplicate rows on network retries.

Fix: Models have zero write tools. Execution requires owner approval of a SHA-256 plan hash.
Biztective (ROOT 2.0) Design Principle: Separate deterministic facts (Fact), evidence-backed root causes (Hypothesis), owner context (Human Input), bounded recovery ranges (Estimate), and verified writes (Action).

03 · STATE MACHINE & HUMAN-IN-THE-LOOP
Durable LangGraph Checkpoints in PostgreSQL

Ten-Stage Verified Pipeline Across Human & Container Restarts

Investigations pause cleanly at awaiting_human in PostgreSQL and resume under per-thread transaction advisory locks without holding open HTTP connections or process memory.

INVESTIGATION SUBGRAPH (10 NODES)

Evidence Gathering → Critic → Clarification

  • load_context → plan_checks → run_verification: Executes deterministic SQL checks for return spikes, vendor defect clusters, and margin drops.
  • critic → decide_next: Verifies sample size, time coverage, and non-contradiction before admitting findings.
  • ask_human (HITL) → incorporate_human: Pauses for up to 3 targeted owner questions; creates a new immutable interpretation_versions row (v1 → v2) on every answer.
RECOVERY & GOOGLE SHEETS EXECUTOR

  • Decision Panel: Owner approves, requests revision, or rejects a specific (plan_id, version, content_hash).
  • actions/executor.py: Reconciles existing sheet keys, appends missing rows, and reads back every cell (pending → succeeded → verified).

05 · CONTAINER PORTABILITY & SAME-ORIGIN SECURITY (AMD-22)
ADR-010 · SEC-02 · SEC-03

Solving Build-Time Next.js Rewrites for Portable Cloud Containers

Next.js evaluates next.config.ts rewrites() at next build time. On Clouds, service URLs are assigned when deployed — so we engineered request-time proxy rewriting in apps/web/src/proxy.ts.

REQUEST-TIME PROXY (apps/web/src/proxy.ts)

Dynamic BACKEND_URL Resolution

  • Intercepts /api/v1/:path* at request time inside the Next.js server runtime.
  • Reads process.env.BACKEND_URL injected via acc services env set without rebuilding the image.
  • Generates per-request cryptographic CSP nonces (script-src 'self' 'nonce-...') on all HTML routes.
FIRST-PARTY HTTPS COOKIE CONTRACT

__Host- Cookies + Signed Double-Submit CSRF

  • Browser only talks to https://root-web-app.alternatefutures.ai — zero third-party cookie blocking.
  • __Host-root_session (Secure; HttpOnly; SameSite=Lax; Path=/) and __Host-root_csrf (SameSite=Strict).
  • Backend CsrfMiddleware validates Origin == FRONTEND_ORIGIN + HMAC-SHA256 session-bound token.

06 · PHASE 10 TECHNICAL HARDENING AUDIT (AMD-21)
16 Material Findings Remediated & Regression-Locked

Hardened Against Concurrency Races, Stale Workers & Ambiguous Writes

F10-01 · F10-02 Auth & Quotas

Serialized Login Throttling & Session Buckets

Ordered PostgreSQL transaction advisory locks serialize concurrent login attempts (12 parallel bad logins → exactly 5 401s and 7 429s; Argon2 offloaded from the event loop). Added 300 req/min session token bucket.

F10-05 · F10-06 Job Queue

Attempt-Fenced Worker Leases

Every job heartbeat, completion, and failure update is fenced by (job_id, status='running', attempts=leased_attempt). A stale worker replaced after lease expiry cannot overwrite the new worker or fire duplicate failure hooks.

F10-09 · F10-10 · F10-11 External Actions

Pre-Mutation Recheck & Crash Reconciliation

Approval & integration binding are re-verified in PostgreSQL immediately before every external HTTP mutation (including tab creation). Post-redirect Apps Script errors are marked ambiguous and reconciled via read-back before any retry.

Recursive Log Redaction (F10-03)

Structured JSON logger recursively redacts nested secret keys, strips SQLAlchemy bound parameters (hide_parameters=True), and logs only exception class + frame locations so credentials never leak to container stdout.

500k-Row Window-Function Deduplication (F10-16)

Replaced NOT IN retained-ID materialization with single-pass row_number() OVER (PARTITION BY key ORDER BY source_row), cutting 500,000-line upload + ingestion from >146 s to 50.37 s.

Redeploy & Rollback Workflow

Clouds caches image tags on provider nodes and rejects mutable :latest or :main tags. Every update bumps the version tag in .github/workflows/deploy-images.yml and deploys via acc: 

# 1. Deploy new versioned frontend & backend images on Clouds
acc services deploy cmvbx1b1016uebs1u7l6ge6p7 \
  --image ttl.sh/root2-mahateer-web-1.0.3:24h -y
acc services deploy cmvbwfap014pibs1u7pxz2e5k \
  --image ttl.sh/root2-mahateer-api-1.0.3:24h -y

# 2. Inspect structured JSON container logs
acc services logs cmvbwfap014pibs1u7pxz2e5k

# 3. Instant rollback to previous known-good tag
acc services deploy cmvbwfap014pibs1u7pxz2e5k \
  --image ttl.sh/root2-mahateer-api-1.0.2:24h -y
TRANSPARENCY · KNOWN LIMITATIONS AF Brand Voice

What Is Scoped & Bounded Today

  • Ephemeral Registry (ttl.sh): Image tags expire after 24h; trigger deploy-images.yml before redeploying after 24 hours.
  • Single-Instance Process State: SEC-20 session rate-limit buckets live in process memory (--workers 1) and reset on container restart.
  • Apps Script Bridge Latency: Google Apps Script redirects take 2–19 s per call; bounded by 45 s timeouts and read-back reconciliation (AMD-20).
  • Deferred Baseline Items (AMD-15/17/18): Data overlays, Slack webhooks, and self-registration UI remain out of scope by design.

Safe Schema Rollback Contract (R-14)

Container image rollbacks do not auto-downgrade PostgreSQL. All Alembic migrations follow expand → migrate → contract so the previous container tag stays compatible with the live schema.
